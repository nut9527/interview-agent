# 核心规则与接口契约

更新：2026-10-26。当前业务模块为 auth、resume、jobs、interview、ai；application 编排跨模块账号生命周期。模块职责见 [架构](architecture.md) 与 [模块边界](后端模块边界.md)。

## 规则与编排

| 范围 | 确定性规则 | 应用编排 |
| --- | --- | --- |
| 私有目标岗位 | `jobs.domain.TargetJobRules`：JD 要求拆分、原文引文与简历证据定位 | `TargetJobService` 校验本人归属、参数与 revision，Repository 管理持久化 |
| 模拟面试 | `InterviewTransitions`：轮次、题号、回答回放与结束；`InterviewAgentPolicy`：材料计划、允许动作、预算与原文证据校验 | `InterviewStateMachine` 读取材料、固定难度与快照，处理额度、模型、租约和提交 |
| 共享文本 | `common.text.SkillLexicon`：技能别名与词边界 | 不访问数据库、身份或模型 |

简历正文与版本历史在同一事务保存，revision CAS 防止覆盖过期编辑。AI 优化建议只在用户审阅后写入表单草稿，持久化仍走正常简历保存。模型协议与调用保护位于 ai，业务 Prompt 与结构校验分别属于 resume 和 interview。

ArchUnit 检查五个业务模块的公开 API 边界、无环依赖、Controller 分层和 domain 基础设施禁令。私有岗位规则限制为数据与确定性 JDK 类型；面试规则另有严格数据白名单。工作流 API 和模型适配器的白名单必须指向仍存在的生产类型，防止删除功能后留下空约束。编译反例覆盖跨模块仓储访问、业务服务回调、时钟、Spring 注解和越界模型依赖。这些是静态依赖约束，不证明反射或所有运行时行为。

## 错误与兼容

统一响应包含 `success/message/data/code`。成功时 code 为 null，失败时是 `ErrorCode` 字符串，HTTP 状态仍有独立含义。客户端按 code 或 HTTP 状态处理，不匹配提示文案。

当前业务码包括注册用户名冲突、简历 revision 冲突、目标岗位 revision 冲突、面试状态冲突和额度耗尽。通用错误覆盖参数、鉴权、资源、媒体类型和上游故障。Security 的 401/403 也返回统一 JSON；请求追踪通过响应头 `X-Request-ID`。完整枚举以 [ErrorCode.java](../backend/src/main/java/cn/edu/whu/zhizhida/common/ErrorCode.java) 为准。

历史面试的 preparation 数据继续保留读取兼容。错误码不复用含义；旧服务或 Mock 缺码时，前端按 HTTP 状态回退。

## 契约检查

1. **实际接口 → 快照**：`OpenApiContractTest` 加载真实 Controller、DTO、Jackson 和 `OpenApiConfig`，仅模拟 Controller 协作者，不连接业务数据库。检查全部 `/api` 路由被导出，去掉动态 servers 并排序对象键，再与 `contracts/openapi.json` 比较。
2. **快照 → TypeScript → 页面 DTO**：`scripts/api-contract.mjs` 生成 `frontend/src/types/generated/openapi.ts`。`check` 拒绝过期生成文件；`api.contract.ts` 递归核对保留页面的请求、响应、分页、嵌套数组与枚举，编译反例防止检查器被弱化。不能手工编辑生成的 TypeScript。
3. **当前快照 → Git 基线**：比较指定提交中的旧契约，拒绝保留接口的路由、字段、响应、类型、认证或必填约束破坏；允许新增接口和可选字段。仅请求使用的数值范围、字符串长度约束可兼容放宽。文案变化不算结构变更。

产品收敛的明确退役项列在 [interview-focus-retirements.json](../contracts/interview-focus-retirements.json)：只对清单中的旧路径、启动请求来源字段及历史诊断载荷转换应用豁免，删除它们后不可重新引入。保留接口仍受兼容门禁约束，重新生成快照不能绕过检查。

本地不传基线时，`check` 只验证生成文件一致性。传入 Git ref 后才比较历史契约；CI 强制要求基线可读。当前目录不是 Git 仓库或缺少目标提交时，不能声称完成了 Git 基线兼容验证。[GitHub Actions](../.github/workflows/verify.yml) 为 PR、push 和手动执行选择相应基线。

## 变更流程

```powershell
# backend/：接口变更后导出实际契约，审阅快照差异
mvn '-Dtest=OpenApiContractTest' '-Dcontract.update=true' test
# 根目录：生成、检查及兼容策略反例
node scripts/api-contract.mjs generate
node scripts/api-contract.mjs check
node --test scripts/api-contract.test.mjs
# 有可读 Git 基线时，额外执行；替换成实际目标提交
node scripts/api-contract.mjs check origin/main
# frontend/
corepack pnpm contract:check
```

CI 不开启 `contract.update`。新增页面 DTO 应登记递归断言；新增错误码、生成器能力或有意退役接口需明确审阅并补充有意义的验证。

生成器只支持当前 OpenAPI 3.0 子集，未知关键字或未解析引用会失败。UI 类型仍承载历史 optional/null 和部分窄字符串集合；运行值、未在注解中声明的业务语义、模型质量和部署顺序需要业务测试及人工核对。验证记录见 [产品收敛回归](evidence/2026-10-26-interview-focus.json)。
