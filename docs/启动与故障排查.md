# 启动与故障排查

最后核对：2026-10-26。

## 推荐启动方式

安装 JDK 17+、Maven 3.8+、Node 20.19+（20.x）或 22.12+。默认数据库模式需要已运行的 Docker Desktop / Docker Compose；已有 MySQL 时可使用 `--external-db`。

Windows 双击根目录 `start.cmd`，或在终端运行：

```powershell
node scripts/dev.mjs
```

启动流程为：环境与端口检查 → 前端依赖检查 / 必要时按锁文件安装 → 复用或下载 MySQL 镜像 → MySQL 容器就绪 → Maven 编译打包 → 后端启动及 Flyway 迁移 → 数据库就绪接口成功 → Vite 启动 → 前端代理就绪。

脚本默认绑定本机 `127.0.0.1`，页面 5173、后端 8080、Compose MySQL 3307。前端可以热更新；后端以本次重新构建的 JAR 启动，改 Java 代码后重启启动器。启动构建跳过测试执行，日常提交前仍需单独运行测试。

| 命令 / 参数 | 行为 |
| --- | --- |
| `node scripts/dev.mjs check` | 只做预检；不安装依赖，不启动容器或应用，不验证数据库凭据 |
| `node scripts/dev.mjs --external-db` | 连接已有 MySQL，不调用 Docker；先检查 TCP，再由 Spring/Flyway 和就绪接口验证真实连接 |
| `node scripts/dev.mjs --offline` | MySQL 必须已有缓存镜像，缺少则立即失败；Maven、npm/pnpm 使用离线模式 |
| `node scripts/dev.mjs --install` | 重新安装锁文件依赖；可用于目录迁移后依赖链接损坏 |
| `node scripts/dev.mjs --mock-ai` | 本次后端使用 Mock AI；不会覆盖 `.env` 中的真实模型配置 |
| `node scripts/dev.mjs --help` | 查看参数 |

不需要运行 `corepack enable`、切换全局 pnpm 或修改全局 Maven 配置。启动器通过项目内 npm 缓存调用固定 pnpm 9.15.9，安装使用 `--frozen-lockfile`，pnpm store 在项目内；已有可用依赖时不重复安装。依赖安装以 `frontend/pnpm-lock.yaml` 为准，请勿混用 `npm install` / `npm ci`。

## 配置与端口

根目录 `.env` 可选；已有文件会保留。支持 `KEY=value`、整值引号、注释和空值，不执行 Shell，也不展开 `${...}`；进程环境变量优先。密钥只传入子进程环境，不拼进命令行。

```properties
# 本地开发端口
BACKEND_PORT=8181
DEV_FRONTEND_PORT=5174

# 真实模型可稍后配置；Mock 不需要密钥
AI_PROVIDER=mock
```

`FRONTEND_PORT` 是 Docker Nginx 的宿主机映射端口，与本地 Vite 端口分开。启动器自动把 `BACKEND_PORT` 同步到后端 `SERVER_PORT` 和 Vite 的 `VITE_API_PROXY_TARGET`。单独从前端目录运行 Vite 时，可以手动设置该代理变量。

已有 MySQL 示例（不要填写生产库）：

```properties
SPRING_DATASOURCE_URL=jdbc:mysql://127.0.0.1:3306/zhizhida?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
SPRING_DATASOURCE_USERNAME=zhizhida
SPRING_DATASOURCE_PASSWORD=替换为本地密码
```

然后运行 `node scripts/dev.mjs --external-db`。如果设置了外部 JDBC URL 却未加该参数，脚本会提示修正，防止无意启动一个与目标连接无关的容器。脚本接受单主机 MySQL JDBC URL；不负责解析多主机负载均衡 URL。

默认容器模式沿用项目的开发库和命名卷，`MYSQL_PORT`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD` 同时用于容器与本地后端。`.env.example` 中数据库密码使用注释占位，避免复制空值后导致 Compose 默认密码与 Java 空密码不一致。正式部署必须自行配置强密码。

### 镜像来源与首次下载

启动器先检查两个官方来源的本地镜像：`docker.io/library/mysql:8.4` 和 `public.ecr.aws/docker/library/mysql:8.4`，任一个已缓存即可复用。都没有时先下载 Docker Hub 镜像；失败或停滞后尝试 ECR 一次，两个来源都失败则退出并显示原因。下载成功后 Compose 使用 `--pull never`，因此“启动数据库”阶段不会再暗中下载镜像。

`MYSQL_IMAGE` 可指定完整镜像名（包括已缓存镜像），优先级高于 `DOCKER_REGISTRY`；这两个变量任一个显式配置时，仅使用指定来源，不会自动替换。直接运行 `docker compose up` 的默认 MySQL 来源为 Docker Hub，不包含启动器的备用源逻辑。镜像选择只通过本次 Compose 进程环境传递，不覆盖 `.env` 或修改 Docker 全局配置。

控制台每 15 秒显示最近一次有效进展，例如 `Downloading 3MB/132MB`；重复打印相同层的相同下载字节不算新进展。日志中的 `Pulling`、`Downloading` 表示还在获取镜像，尚未开始初始化 MySQL。两个官方来源都下载失败时，应检查 Docker Desktop 的网络/代理连接；重新运行不会删除已有数据卷。

## 停止、日志与失败行为

- Ctrl+C 停止本次启动器创建的前后端进程及其子进程；不会按端口、程序名批量结束已有进程。
- 数据库容器继续运行，数据保留。需要停止本项目数据库时执行 `docker compose stop mysql`；不要用删除数据卷来修复登录失败。
- 日志位于 `.runtime/<时间与进程号>/`，分别为 `install.log`、`mysql-image-1.log`、`mysql-image-2.log`、`mysql.log`、`build.log`、`backend.log`、`frontend.log`；只生成实际执行阶段的日志。控制台摘要隐藏环境中的凭据，完整本地日志不要直接公开。该目录已被 Git 忽略。
- 一次性安装、每次镜像下载、容器启动和编译阶段连续 2 分钟没有新进展或总计超过 4 分钟会终止当前命令；镜像下载只允许上述一次备用来源尝试。后端就绪最多等待 90 秒，前端代理最多等待 30 秒。超时或服务意外退出会停止本次其他应用进程。
- Windows 双击脚本失败后保留错误窗口，便于阅读；命令行自动化建议直接调用 Node 入口。

## 本轮发现与修复的问题

| 问题 | 修复 / 处理 |
| --- | --- |
| `mvn spring-boot:run` 默认强依赖 Docker，即使已有 MySQL 也在 Docker 不可用时失败 | Spring 自动 Compose 默认关闭，根目录脚本显式选择容器或外部库；可手动重新开启自动管理 |
| 后端退出自动停止共享 MySQL | 可选自动管理改为 `start-only`；启动器退出保留数据库 |
| `.env` 的数据库端口 / 用户 / 密码只作用于 Compose，本地后端仍使用固定默认值 | Java 配置增加 MYSQL 变量回退，启动器统一连接参数，外部 SPRING_DATASOURCE 配置优先 |
| 前端写死代理到 localhost:8080，端口被占用时又会自动换端口 | 代理目标可配置，启动器同步端口，Vite 固定使用 IPv4 本机地址并启用 strictPort |
| 复制环境模板后默认启用 DeepSeek，但密钥为空 | 新模板默认 Mock；已有真实模型配置保留，无密钥时预检提示，不静默降级 |
| 健康检查固定显示 in-memory-demo 和硬编码版本，不反映数据库就绪 | 存活接口显示 MySQL 与 Maven 版本；新增 `/api/health/ready`，失败为 503 |
| Docker 后端健康探针依赖镜像内存在 curl | 使用镜像已有 Java 运行探针，不再要求 curl/wget；探针检查数据库就绪接口 |
| 缺少统一启动路径、故障日志和组件退出清理 | 新增跨工作目录的 Node 启动器及 Windows 入口，按步骤等待、记录日志并管理本次子进程 |
| 镜像下载停滞却一直显示“等待 mysql”，误以为数据库卡死 | 将镜像下载与数据库就绪拆开；显示最近有效进展、缓存复用、停滞超时和官方备用源；离线模式禁止隐式拉取 |

## 常见错误

| 提示 / 现象 | 操作 |
| --- | --- |
| Docker 引擎未运行 | 打开 Docker Desktop，等引擎就绪；或配置已有 MySQL 并加 `--external-db`。脚本不会擅自启动系统应用 |
| `mysql-image` 一直显示相同下载字节 / 下载失败 | 尚未启动数据库。脚本会有界退出/尝试备用来源；检查 Docker Desktop 网络/代理，或用 `MYSQL_IMAGE` 指定已有的 MySQL 8.4 镜像 |
| 离线启动缺少 MySQL 镜像 | 先联网完成一次镜像下载；`--offline` 不会再后台尝试拉取 |
| 5173 或 8080 被占用 | 先确认现有进程用途；关闭自己不再需要的服务，或修改开发端口。脚本不会强杀占用者 |
| MySQL 端口可连，后端仍报 Access denied | 核对目标库和用户密码。MySQL 已有数据卷时，修改环境变量不会自动修改数据库中已有账号的密码 |
| Flyway checksum / migration 错误 | 查看本次 backend.log，核对历史迁移与目标数据库；不要自动 repair 或删除数据卷 |
| 后端 JAR 不唯一 | `target` 可能保留多个旧版本，人工确认后移走过期版本；脚本不猜测、不删除 |
| 依赖缺失、旧路径链接、锁文件错误 | 执行 `--install`，使用固定 pnpm 与锁文件；首次安装需要网络；不要全局切换 Node/pnpm 来掩盖错误 |
| Node 子进程报 spawn EPERM | 执行环境阻止了子进程；使用正常本地终端，或为当前项目构建/检查命令授权；不需要修改项目源码绕过安全策略 |
