## 接口调用示例

下面用 PowerShell 在默认 Mock 环境中完成一次单轮岗位面试。普通岗位面试接口接受 1–12 轮，这里用一轮走完开场、作答和复盘。网页通过 SSE 展示进度，终端示例使用任务返回的 `statusUrl` 查询结果。

```powershell
$origin = 'http://127.0.0.1:8080'
$token = (Invoke-RestMethod -Method Post -Uri "$origin/api/auth/demo").data.token
$headers = @{ Authorization = "Bearer $token" }

function Invoke-InterviewRun($path, $command) {
    $request = @{
        Method = 'Post'
        Uri = "$origin$path"
        Headers = $headers
        ContentType = 'application/json; charset=utf-8'
        Body = $command | ConvertTo-Json -Depth 4
    }
    $run = (Invoke-RestMethod @request).data
    $deadline = (Get-Date).AddMinutes(2)
    while ($run.status -in 'ACCEPTED', 'RUNNING' -and (Get-Date) -lt $deadline) {
        Start-Sleep -Seconds 1
        $run = (Invoke-RestMethod -Uri "$origin$($run.statusUrl)" -Headers $headers).data
    }
    if ($run.status -ne 'SUCCEEDED') { throw "任务 $($run.runId) 当前状态 $($run.status) $($run.errorCode)" }
    return $run
}

$start = @{
    requestId = [guid]::NewGuid().ToString()
    configuration = @{
        targetRole = 'Java 后端工程师'
        jobDescription = '负责订单与库存服务，熟悉 MySQL 事务及并发控制。'
        totalRounds = 1
        experienceMode = 'TEACHING'
    }
}
$opening = Invoke-InterviewRun '/api/interviews/start-commands' $start
$sessionPath = "/api/interviews/sessions/$($opening.sessionId)"
$session = (Invoke-RestMethod -Uri "$origin$sessionPath" -Headers $headers).data
$session.turns[-1].content

$answer = @{
    requestId = [guid]::NewGuid().ToString()
    expectedTurn = $session.turnCount
    answer = Read-Host '输入你的回答'
}
Invoke-InterviewRun "$sessionPath/answer-commands" $answer | Out-Null
$review = (Invoke-RestMethod -Uri "$origin$sessionPath" -Headers $headers).data
$review.turns | Format-Table speaker, content -Wrap
```

开场命令和作答命令均返回 HTTP 202。开场任务成功时取得 `sessionId`，回答任务成功后会话的 `state` 为 `FINISHED`。`turns` 按顺序给出问题、你的回答、反馈和总结。

## 开发与验证

**面试提示词维护。** `InterviewPromptBuilder` 使用的八份模板位于 `backend/src/main/resources/prompts/interview/v1/`，`version.txt` 记录模板包版本，正文使用 UTF-8。默认加载随应用打包的模板；独立部署模板时，将完整目录复制到部署环境，设置 `INTERVIEW_PROMPT_DIRECTORY`（或 Spring 属性 `interview.prompts.directory`）为该目录的绝对路径，修改模板及版本后重启 API/Worker。拆分部署的实例使用同一模板包，启动校验检查文件完整性、正文和路由占位符。

模板在启动时加载为不可变快照，`templateManifest()` 将版本和正文纳入运行配置指纹。更新前先完成或取消在途任务，再统一切换 API/Worker 和模板包；指纹不匹配的任务返回 `MODEL_CONFIG_CHANGED`。`routing.txt` 包含按动作、追问类型排列的两个 `%s` 占位符，字面百分号写为 `%%`。输出契约及路由校验由 Java 代码维护。

`interview-prompts-v5` 压缩输出契约和反馈篇幅，保留六维观察、引用与路由约束。各维先选引文，再给出引文覆盖的单条观察；缺少替代方案比较或代价时，取舍维度保持未知。最终轮的结束动作、目标能力、追问类型和下一题字段由服务端根据轮次构造，非最终轮的题目能力标识由目标能力派生，模型负责评审内容与仍需选择的路由。

**本地源码启动。** 准备 JDK 21、Maven、Node.js 22.14+（含 npm）和 Docker Compose，在根目录执行 `node scripts/dev.mjs --mock-ai`。Windows 也可以执行 `.\start.cmd --mock-ai`。启动器拉起 MySQL、Redis 和 RabbitMQ，启动本地 MCP 资料服务、后端和 Vite。开发页面默认使用 [5173 端口](http://127.0.0.1:5173/)，后端默认使用 8080。使用已有 MySQL 与协调 Redis 时，配置连接地址并加上 `--external-db` 跳过容器启动。[运行指南](../docs/启动与故障排查.md)

**持续集成。** [Verify 工作流](../.github/workflows/verify.yml) 先用 `.env.example` 校验 Compose 主配置、split、middleware 及二者叠加的四种组合，并检查接口契约和交付包登记；通过后并行执行后端、前端与浏览器任务。后端检查源码格式、单元与 MySQL/Redis 集成测试、覆盖率、LangChain4j 协议兼容及容器启动；前端检查格式、类型、Lint、单元测试和生产构建。脚本测试按 `*.test.mjs` 自动收集，覆盖文档链接、MCP 资料服务、启动器、真实 Vite 代理和 Java 21 健康探针。

**浏览器核心流程。** 工作流的 `browser` 任务使用锁定的 Playwright 与配套 Chromium、一次性 MySQL 8.4 和 Redis 7.4.2，验证「进入独立演示空间 → 三轮面试 → 刷新恢复 → 能力复盘」。浏览器访问真实前端、后端及数据库，检查回答持久化、SSE 成功和刷新不重发；只有模型使用 Mock。这项通过不代表真实模型质量验收通过。每次报告与截图保存在 `outputs/browser-e2e/run-*/`，CI 无论成功或失败均上传该目录，失败时另附服务日志。

本地需要 JDK 21、Maven、Node.js 22.14+、pnpm 9.15.9，以及 PATH 中的 `mysqld`、`mysql`、`mysqladmin` 和 Redis 6+。在项目根目录依次执行：

```sh
cd backend
mvn -DskipTests package
cd ../frontend
pnpm install --frozen-lockfile --store-dir ../.pnpm-store
pnpm browser:install
pnpm build
pnpm test:browser-tools
pnpm test:e2e
```

Windows 可使用已安装的 WSL Redis：运行验收前在 PowerShell 设置 `$env:BROWSER_REDIS_WSL_DISTRO = 'Ubuntu'`；也可用 `BROWSER_REDIS_EXECUTABLE` 指定原生 Redis。脚本只使用空闲的 13308、16379、18080、15173 回环端口，创建本次独占的数据库和 Redis 进程，不读取开发 `.env`，退出时关闭进程并清理临时数据；已有服务占用这些端口时会直接报错。`--ci-services` 仅用于 `CI=true` 的一次性 CI 服务，不用于开发数据库。

`pnpm browser:install` 将浏览器保存在项目 `.cache/ms-playwright`；Linux 若缺系统库，可在准备好的测试环境使用 `pnpm browser:install --with-deps`，CI 已执行此步骤。现有专项浏览器脚本也默认使用该 Chromium，可通过 `PLAYWRIGHT_BROWSER_CHANNEL=msedge` 或 `PLAYWRIGHT_EXECUTABLE_PATH` 显式选择其他浏览器。浏览器安装方式参考 [Playwright 官方文档](https://playwright.dev/docs/browsers)。

**模型评测。** 验收登记定义工具取证、引用支持、追问相关性和复练衔接等检查项，包含 12 个场景及 6 轮面试接 3 轮复练的流程。各批次状态、检索对照指标和原始记录集中维护在[验证记录](../docs/evidence/README.md)，场景与通过标准见[验收登记](../contracts/release-v1.0.json)。

**真实运行复核。** 真实模型单轮 Worker 持久化及针对性语义复核、RabbitMQ 六项故障场景、前端与 MCP Docker 冒烟均已有通过记录，范围见[运行验收汇总](evidence/runtime-acceptance.md)。这些结果不代表完整发布、多轮表现或稳定率验收通过。

以下命令从项目根目录执行：

```sh
node scripts/verify-provider-lifecycle.mjs --prepare
node scripts/verify-provider-lifecycle.mjs --real --stage=manual-check --max-requests=8 --max-output-tokens=16000
node scripts/verify-run-retry-live.mjs
node scripts/verify-web-containers-live.mjs
```

- **真实模型生命周期：** 需要 JDK 21、Maven、Node.js、Docker，PATH 中的 `mysqld`、`mysql`、`mysqladmin`，项目 `.m2/repository` 中的离线依赖、缓存的 `redis:7.4.2` 镜像及空闲端口 13327。读取 `.env` 或环境变量中的 `AI_API_KEY`／`DEEPSEEK_API_KEY`，仅允许官方 DeepSeek HTTPS 地址；`--prepare` 不发起推理。`--real` 使用合成材料执行生产 Worker，最多 8 次生成、16,000 输出 tokens，不自动付费重跑。每次换用未使用过的 `--stage`；逐次响应、校验、用量和构建报告保存在 `backend/target/provider-simplified/<stage>/`。
- **RabbitMQ 故障恢复：** 需要 JDK 21、Maven 离线依赖、Node.js、Docker，以及缓存的 `mysql:8.4`、`redis:7.4.2`、`rabbitmq:4.1.0-management` 镜像；端口 13317 必须空闲。使用 Mock 模型与独占容器验证真实 API、SQL、AMQP 故障恢复；报告写入 `docs/evidence/rabbitmq-retry-live-<run>.json`，日志和测试报告保存在 `backend/target/mq-acceptance/`。
- **前端与 MCP 容器：** 需要 Node.js、Docker 及镜像构建所需的基础镜像和依赖下载条件。脚本构建镜像，通过随机回环端口检查前端静态资源、SPA 路由、安全响应头及 MCP 初始化、搜索和非 root 运行；不执行前后端联调。报告写入 `docs/evidence/web-container-smoke-<run>.json`，构建日志保存在 `outputs/web-container-acceptance/<run>/`。三个脚本均清理自身创建的服务和临时数据，保留验收产物。

在根目录运行 `node scripts/release-status.mjs check`，可只读核对冻结登记、历史台账哈希链并输出当前验收范围；命令成功表示状态清单可读取、登记与台账检查通过，不表示 AI 发布验收通过。发布门禁可运行 `node scripts/release-status.mjs require-accepted`，当前候选会以非零退出码拒绝通过。两条命令均不读取模型密钥、不发起推理，也不修改登记或历史证据。

**交付源码。** 在根目录执行 `node scripts/release-candidate.mjs create interview-platform`，生成标准应用源码包。将 `interview-platform` 换成未使用过的名字；脚本按白名单复制源码、文档和回放数据（含 `services/embedding/`），连同文件清单及 SHA-256 摘要写入 `outputs/release/<名称>/`。在项目根目录执行 `node scripts/release-candidate.mjs verify outputs/release/<名称>` 检查文件完整性。[打包规则](../scripts/release-candidate.mjs)
