# AI 优化比较与撤销

更新：2026-10-02。状态：已验证（前端回归与本地浏览器受控 API）。没有调用真实模型、操作业务数据库或发布服务。

## 使用流程

简历编辑页支持个人简介与单个结构化项目的个人贡献。点击对应 AI 优化后，原文保持可编辑；返回结果只显示建议。先比较划线原文与下划线建议，再勾选要采用的修改，点击「采用所选」。可以逐条拒绝或拒绝全部剩余建议，拒绝不会修改文字。

采用与撤销只改变当前表单；保存通过原有 POST／PUT 简历接口完成。已有简历保存后只更新 revision，不重新读取覆盖表单。首次创建后保持编辑实例，保留请求期间的新输入和撤销记录；继续输入的内容需要再次保存。刷新或切换简历／账号后，仅已保存的内容可恢复；建议和撤销记录不持久化。

## 状态与安全规则

| 操作 | 规则 |
| --- | --- |
| 生成 | 捕获目标字段原文与目标岗位；每字段独立请求编号、AbortController 和账号作用域 |
| 展示 | 结果不写入表单；默认不选中修改；提供完整原文／优化稿、逐处差异、理由和后续建议 |
| 采用 | 当前字段须等于「生成时原文 + 已采用修改」，目标岗位也须一致；否则保留输入并要求重新生成 |
| 部分采用 | 只写入勾选片段；未选和已拒绝内容保持原状；再采用剩余片段时重新核对 |
| 撤销 | 每字段按采用批次后进先出；计算逆向修改，仅在与后续手工编辑不重叠时应用；保留外围新文字 |
| 撤销冲突 | 不写入任何内容，保留撤销记录，提示对照原文手动调整 |
| 取消／卸载 | 请求中止并递增编号，忽略迟到成功和失败；切换账号使原控制器失效 |
| 删除项目 | Form.List 的稳定 key 绑定控制器；前项删除只改变路径，删除目标本身会销毁控制器 |
| 模型或网络错误 | 保留草稿，展示请求层错误，允许用户重试；无自动重复生成 |

取消客户端请求不保证模型侧停止执行，也不保证退还调用额度。服务端归属、revision CAS 与事务仍保护持久化更新；本功能处理的是编辑页内模型响应和用户输入之间的竞争。

## 差异算法与边界

`textReview.ts` 按句末标点和换行分段，以有界 LCS 对齐相同片段，再把变更段配成可选择修改；共同前后缀按 Unicode 码点裁剪，位置采用 JavaScript 字符串偏移，空白与换行原样保留。全部采用可重建完整优化稿，不依赖模型提供偏移或可执行补丁。`improvements` 只作为解释和参考表达展示。

任一侧超过 200 个分段时，合并为一处差异，避免标点密集输入导致二次方内存和大量卡片。撤销把一次采用的变化包络视为一个范围，把之后手工编辑的变化包络视为另一个范围；不重叠才自动撤销。多个分散手改可能被保守判为冲突；不承诺任意文本编辑的自动三方合并，也不推断重复文字的语义归属。

沿用 `POST /api/ai/resume/optimize` 的 `{rawText, targetRole}` 契约。项目贡献按换行拼接，采用后按换行恢复数组；不传整份简历、不改变项目其他字段。输入最多 8000 字、岗位 120 字，输出按既有上限 12000 字核对；项目采用后还需满足不超过 30 条、每条非空且最多 3000 字，失败时明确提示且不截断。

当前不包含旧项目补充文本、实习经历或整份简历批量优化。模型结果仍需人工核对事实。页面刷新、离开、账号切换和显式恢复历史版本后不保留建议／撤销栈；历史保存版本可继续使用原有版本恢复功能。

## 实现与复现

- `frontend/src/components/resume/AiTextOptimizer.tsx`：复用 UI，支持键盘选择、独立状态提示与手机单列比较。
- `optimizationController.ts`：生成、选择、拒绝、采用、撤销和请求生命周期，纯接口注入便于控制延迟测试。
- `textReview.ts`：文本差异、应用和保守撤销。
- `frontend/src/pages/Resumes/Editor/index.tsx`：简历／账号实例隔离、首次创建延续草稿和保存回包保护。
