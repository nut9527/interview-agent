# 简历编辑与导入可靠性

更新：2026-10-03。状态：已验证（本地前后端自动化与受控浏览器）；未发布。

## 用户流程

列表入口为 `/resumes`，新建和编辑在 `/resumes/edit`，保留内容预览、浏览器打印和版本历史。

导入：选择 PDF／DOC／DOCX → 只解析 → 在完整编辑表单中检查纠正 → 必填及结构化字段校验 → 确认创建。未确认不产生简历记录，取消／错误响应不导航、不生成新草稿。再次解析需确认替换已有导入草稿，解析失败保留旧稿。纠正页和普通编辑共用字段及控制器，含电话、邮箱、链接、教育和项目；保留既有 5 MB／30 页／100000 字符限制，无 OCR。

编辑：加载服务器 → 若有草稿，提示恢复／丢弃 → 显示未保存状态 → 保存提交时的快照 → 更新修订号及保存时间。保存中可以继续输入，新输入仍标未保存，不因回包回填而消失。初次创建迁移草稿键到新 ID，保留相同表单和 AI 撤销记录；再次新建使用独立编辑实例。

409：读取最新版 → 比较基线、当前输入与服务器内容 → 选择 → 返回编辑 → 再保存。独立字段预选实际修改的一方，双方修改需手动选择；邮箱、电话、城市独立比较，教育、项目、链接列表整体选择，避免将删除或换序后的数组下标当作条目身份。可以稍后处理并继续编辑；重新打开使用当前输入重新比较。

## 草稿生命周期与数据隔离

- `resumeDraft.ts` 用 sessionStorage，键含 schema 版本、用户 ID、简历 ID；新建和导入使用各自键。内容包含基线、原始表单值、revision 和更新时间；不含 Token、文件二进制、AI 建议或撤销栈。
- 每次表单变化立即暂存，原始多行文字保留未完成行；AI 程序化采用／撤销也由 Form watch 观察。单份编码上限 1000000 字符，超限或存储拒绝显示警告，内存输入不删除。
- 最后编辑起 24 小时有效。加载／解析时扫描过期记录；读取校验账号、键、版本、时间和字段形状。损坏记录忽略并告知；不会使用其他账号的草稿。
- 保存成功且没有后续编辑：删除该稿。有后续编辑：以已提交快照和新 revision 为基线继续暂存。服务器与草稿内容相同则清理旧记录，应对更新成功但回包丢失。
- 明确丢弃、删除对应简历、退出／切换账号／重新登录清理相应草稿。账号重置先取消请求、清缓存，再重新挂载私有路由。旧控制器检查账号代次与卸载状态，不能重新写回存储。
- 站内导航用 useBlocker，刷新／关闭用 beforeunload；退出前确认清理。浏览器负责是否展示原生提示，脚本无法保证强制终止／崩溃时提示。草稿仅限当前标签页；复制标签页的浏览器可能复制初始 sessionStorage，随后各自独立，服务器 revision 继续保证写入冲突保护。

## 请求竞争与乐观锁

`editorController.ts` 独立于 React 表单：同步设置提交锁，加载／冲突读取按请求序号只接纳最新结果，卸载中止请求；即使调用方忽略 AbortSignal，也检查账号作用域及实例状态。保存捕获提交快照，回包不重新填表。比较选择或恢复整份内容时清空旧 AI 建议，普通保存保持撤销记录。

现有后端继续使用 `id + user_id + revision` 条件更新和同事务版本快照。新增 parse 服务先取得当前身份，仅调用解析器，不访问简历和版本 Repository。前端恢复历史时要求先保存修改，恢复期间禁用编辑并使用恢复返回值；过期修订号进入比较流程。

## 明确边界

旧 `/api/resumes/import` 仍直接创建，保留兼容；当前 UI 使用 `/import/parse` 和普通创建，初始版本类型为 CREATED。创建没有服务端幂等键，超时不自动重放，用户需先检查列表；不能宣称创建请求恰好一次。草稿不是跨设备云同步，也不自动定时提交服务器。多个账号隔离依赖后端鉴权及归属条件，本地存储不是安全边界。结构化列表不做条目级三方自动合并。旧客户端省略 revision 仍有过期编辑风险。
