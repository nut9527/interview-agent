# 前端面试会话与请求隔离

更新：2026-10-26。入口为 `/interview`，材料、难度、历史与复盘在同一训练室中组织。

## 职责与状态

- `InterviewSetup.tsx`：选择本人简历、已保存目标岗位或本场自定义 JD，设置难度、方向和轮次。`interviewSettings.ts` 构建互斥来源的启动请求。
- `useInterviewData.ts`：分页读取历史及删除记录，翻页或卸载时取消旧请求；简历和岗位读取由材料准备组件负责。
- `useInterviewSession.ts`：React 订阅与控制器生命周期。有 sessionId 时打开该场；携带 resumeId/targetJobId 的链接进入新场准备；普通入口可以恢复有效的活动会话。
- `sessionController.ts`：创建、恢复、提交、租约轮询、失败退避和取消。server 是服务端快照，draft 是当前回答，ui 保存请求阶段、错误、冷却时间和活动会话编号。
- `pendingAnswer.ts`：按账号/会话/题号分开的短时恢复记录，10 分钟过期；未提交的普通回答草稿只在页面内存中。

创建/提交失败不会伪造成功结果。提交期间锁定回答，防止迟到成功清除用户新输入。切换会话和卸载会取消请求及计时器；已经发出的回答可能仍在后端执行，所以页面跳转保留有效期内的待确认记录。难度与 JD 从服务端会话恢复，创建后不由回答请求修改。

## 回答恢复与失败处理

| 情况 | 行为 |
| --- | --- |
| 刷新或打开历史 | 先 GET 核对；已提交则展示结果，题号变化则丢弃旧回答；租约有效时每 2.5 秒核对，未提交且无租约才用原编号/题号/回答回放 |
| 回答 POST 返回 409 | 自动 GET；同题且未提交时允许明确重试，不循环 POST |
| POST 超时、断网或暂时性 5xx | 保留回答和编号，只自动核对 GET，确认后可手动重试 |
| 429 | 保留输入，遵守 Retry-After 秒数或 HTTP 日期；缺失时等待 5 秒 |
| GET 暂时失败 | 初次加最多两次自动重试，默认延迟 2.5/5 秒，优先遵守 Retry-After；耗尽后提供手动核对 |
| 会话 403/404 | 清除该会话恢复记录和活动标记，停止轮询并显示原因 |

启动面试没有后端创建幂等键，失败后不自动重试。取消客户端请求不能撤回已经发生的写入或模型费用。

## 账号与请求生命周期

身份初始化、显式登录、退出和跨标签页 storage 事件统一经过 authStore。账号 ID 或 Token 改变、显式重新登录时，递增身份代次并中止旧 HTTP 请求，清空简历/版本/比较及面试历史 Store，清除本标签页的简历草稿、面试活动标记和待确认记录，再重新挂载私有页面。资料更新保持同一账号作用域。

请求层和 Store 都核对代次。即使适配器忽略取消，旧成功不能写回新账号，旧失败不能清除新加载状态，旧 401 不能登出新身份。显式前端 Mock 的简历和面试数据也随账号重置；完整材料与 Agent 流程使用真实后端，后端可运行无密钥 Mock AI。

## 结构化错误与验证

ApiError 保留 HTTP status、业务 code、requestId、Retry-After 及解析时间、transportCode 和 cause；HTTP 200 的 success=false 也按失败处理，取消保持 Axios 取消语义。展示错误说明和请求编号，按 code/HTTP 状态分支，不匹配文案。响应头 X-Request-ID 是排障编号，与回答正文的幂等 requestId 不同。契约机制见 [核心规则与接口契约](核心规则与接口契约.md)。

在 frontend 执行 `corepack pnpm test`、typecheck、lint、build；浏览器验收使用 `node scripts/verify-interview-browser.mjs`。测试使用合成数据、延迟 Promise、受控适配器和计时器。产品收敛时的验证范围见 [2026-10-26 记录](evidence/2026-10-26-interview-focus.json)；真实模型效果与生产故障联调需另行验证。
